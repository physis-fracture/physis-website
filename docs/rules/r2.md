# Cloudflare R2 Object Storage Rules

Private Cloudflare R2 bucket for study radiographs. Flow, config, and conventions.

## Flow

```text
Browser → Next.js requests presigned PUT URL → browser PUTs directly to R2
→ Next.js HEAD-verifies → only then INSERT study + images (verified) → presigned GET generated on demand
```

- Image bytes never pass through Next.js.
- R2 credentials never reach the browser.
- Bucket stays private.
- Presigned URLs are never persisted — only `object_key` is stored.

## Object Keys

```text
studies/{study_uuid}/images/{image_uuid}/original.{extension}
```

- extension derived from validated MIME type, never the original filename;
- no patient identifiers, names, or emails in keys.

## Supported Upload Formats

- MIME whitelist: `image/png`, `image/jpeg`, `image/tiff`, `image/bmp`, `image/webp`, `image/gif`
- max file size: 32 MB
- enforced server-side in `features/studies/schemas/new-study.ts` (Zod) and mirrored as a client pre-check in the form.

## Environment Variables

All server-only (no `NEXT_PUBLIC_`):

```env
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=physis
R2_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
```

Validated at module load in `lib/r2/client.ts`; missing values throw.

## Required API Token Permissions

Cloudflare Dashboard → R2 → Manage R2 API Tokens → Create API Token:

- Permission: **Object Read & Write**;
- scope: the `physis` bucket;
- use the token's Access Key ID + Secret Access Key in the env vars above.

## CORS

Dashboard → R2 → `physis` bucket → Settings → CORS Policy. Use only real
frontend origins (no `*` for production):

```json
[
  {
    "AllowedOrigins": [
      "http://localhost:3000",
      "https://<production-domain>"
    ],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["Content-Type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

## Server Responsibilities

`lib/r2/client.ts` (server-only, lazy singleton `S3Client`):

- `generateUploadUrl` — presigned PUT, ~10 min expiry, `ContentType` bound
- `headObject` — HEAD verification
- `generateViewUrl` — presigned GET, ~10 min expiry
- `buildObjectKey` — key from study id + image id + validated MIME

`features/studies/actions/create-study.ts`:

- `createStudy` — auth → validate schema → object keys → presigned PUT URLs. No DB writes.
- `finalizeStudy` — HEAD each object → verify `ContentLength` == `fileSize` and `ContentType` == `fileType` → INSERT study + images (as `verified`) → presigned GETs → inference

Insert happens only after verification, so a failed/abandoned upload leaves no orphan rows.

## Security

- presigned URLs are bearer credentials: short expiry, not logged, not persisted, not in analytics;
- never return raw AWS SDK errors or credentials to the browser;
- no delete helper yet — add one only when the app needs object deletion (YAGNI).

## Local Testing

1. Set the R2 env vars in `.env.local` (gitignored).
2. Set the bucket CORS policy (JSON above).
3. `pnpm dev` → New Study → upload a PNG/JPEG → verify object appears in the `physis` bucket → `finalizeStudy` HEAD-verifies → case detail shows the image via presigned GET.
